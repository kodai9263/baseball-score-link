# 公開準備

確認日：2026-09-11。作業ブランチ：`feature/ui-refresh`。この文書は本番公開の完了報告ではありません。

## 現在の範囲

- 紙スコア表示、走塁入力、複数試合保存、メンバー登録、通算・学年別・期間別の打撃成績。
- 保存先は同じ端末・ブラウザ・URLのローカルストレージ。複数端末での同期はない。
- 全メンバー・試合をJSONに書き出せる。復元時は内容をプレビューし、現在のバックアップを書き出してから置き換える。不正なファイルは拒否する。
- 成績は入力済みの暫定記録から集計。代打・代走・守備交代・守備位置変更、開始前の先攻・後攻交換に対応。詳しくは [選手交代と先攻・後攻](lineup-changes.md)。公式記録判定、投手成績、再出場は未対応。
- 新しい試合で両チーム別にDHを選択できる。投手交代・DH解除・紙スコアへの反映は [DHの選択・交代](dh.md) を参照。先発投手兼DHなどの特殊方式は対象外。

## 公開前に決めること

最初の公開をデモにするか、チームの実際の試合で使うものにするかを確認中。

デモであれば保存が端末内だけであることを明示する。チーム運用なら、ログイン、チームへの招待、チーム単位のアクセス制御、管理者・記録者・閲覧者の権限、クラウド保存・共有を先に実装する。子どもの名前や成績を他チームや未ログインの閲覧者が取得できないことを検証する。

## 必須の残作業

1. 依存関係の更新は完了。Next.js 16.3.4、sharp 0.35.4、nanoid 3.3.18に更新し、インストール時の全依存監査で脆弱性0件を確認。
2. 公開先、URL、管理アカウントと、必要ならSupabaseプロジェクトを確定する。環境変数だけではクラウド保存は動かない。
3. 採用した公開範囲の機能を実装・検証し、テスト・lint・型チェック・ビルドを通す。
4. 公開前に既存記録をバックアップする。ローカルと公開URLでは保存領域が異なるため、自動では移行しない。
5. 承認後にプッシュ・マージ・デプロイし、公開URLでPCとスマートフォンの入力・保存・再読み込み・成績集計を確認する。チーム運用の場合は別アカウントからの権限・同期も検証する。

- 選手交代追加後の自動テスト127件、lint、型チェック、本番ビルドは成功。復元時の複数試合・成績の保持と競合拒否、交代と先後攻交換のテストを含む。型チェックは先に`next typegen`を実行し、初回チェックアウトでもルート型を生成する。
