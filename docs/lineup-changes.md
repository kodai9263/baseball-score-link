# 選手交代と先攻・後攻

2026-09-11実装。既存の試合帳・バックアップを引き続き読み込める。

## 使い方

- 試合管理の「先攻・後攻の入れ替え」でチーム名と打順をまとめて交換する。プレー・交代を記録する前だけ操作できる。次の試合は「新しい試合」で作成してから入れ替える。
- 「メンバー・成績」で控え選手を登録する。所属は、表示中の試合に対応するチーム名で選べる。先攻・後攻を入れ替えてもメンバーの所属や他の試合は変わらない。
- 「選手交代・守備位置」を開く。攻撃側は現在打者の代打、塁上の選手の代走を選べる。守備側は控え選手への守備交代、出場中の選手の守備位置変更を選べる。
- 守備位置を変更すると、その守備位置の選手と位置を交換する。打順は変わらない。
- 「取消」は交代も含め、最後の操作から1件ずつ戻す。交代後にプレーを記録していれば、プレーを取り消してから交代を取り消す。

## 記録・成績

- 開始時の打順は保存したまま、交代のタイミング・打順・交代前後の選手・守備位置を別の履歴に保存する。
- 代打・守備交代・代走では打順の枠を引き継ぐ。交代だけでは打席、アウト、得点を増やさない。
- 代走は塁上の選手IDを置き換え、後続プレーの得点は代走選手に付ける。元の選手の安打や打席はそのまま残す。
- 紙スコアには交代選手を同じ打順の下に別行で表示する。代走後の進塁は元の出塁マスに「代走」と追記して表示し、右側の成績は選手ごとに分ける。
- 交代で入っただけの選手も、その試合を出場試合として数える。打席のない選手の打数は0、打率は「—」。先発選手の守備のみの出場判定は従来どおり未対応。
- 試合日未設定の試合へ入る選手の学年は「学年不明」で保存する。試合情報から試合日と学年を修正できる。

## 検証

全127件の自動テスト、lint、型チェック、本番ビルドに成功。代打の安打、代走の得点、連続交代、交代・プレーの逆順取消、守備交代、守備位置交換、旧形式との互換性、不正な交代履歴の拒否、先攻・後攻の交換と次の試合への所属引き継ぎを確認した。

実画面は検証専用の `localhost:3002` で実施。先後攻交換→再読み込み、控え登録、代打→単打→代走→再読み込み→本塁打、代走の0打席・0打数・1得点、プレー→代走の逆順取消、開始後の先後攻交換禁止、守備位置交換→再読み込み、控えへの守備交代、375px幅での操作を確認。

## 対応範囲

打席途中の投球数は未管理のため、打席途中の交代に伴う三振・四球の帰属判定は未対応。退いた選手の再出場、自由な打順変更、投手成績は未対応。DHは[DHの選択・交代](dh.md)に対応範囲を記載。記録は暫定として扱う。交代履歴のあるバックアップは、この機能に対応した版で読み込む。
