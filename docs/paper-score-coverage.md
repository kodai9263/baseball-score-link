# 写真の記号に合わせた入力と出力

2026-09-10。ローカル試作の対応範囲。

「すべてのプレーから選択」で28種類を選び、守備位置・処理順と、プレー後の各走者の行き先を指定する。盗塁などは打席を増やさず、出塁した選手の元のマスへ追記する。取消はイベントを再生して打順・塁・アウト・得点を復元する。

| 入力 | 紙スコア上の表現 |
| --- | --- |
| 単打・二塁打・三塁打・本塁打 | 守備番号と安打で得た塁までの赤線 |
| 内野安打・バント安打 | 赤線と番号、内野安打の弧・バント安打の丸 |
| 四球・死球・申告敬遠 | B・DB・DIB |
| 三振・振り逃げ | K・反転K |
| ゴロ・犠打 | 5-3などの処理順（犠打はSAC付き） |
| フライ・ファウルフライ・ライナー | 番号の上に弧・弧とF・横線 |
| 野手選択 | FCと処理順 |
| 失策出塁・失策による進塁 | 6E・5-3Eなど |
| ワンヒットワンエラー | 安打の赤線・番号と、その後の進塁先の失策番号E |
| 盗塁・盗塁死 | S・CSと処理順 |
| ボーク・暴投・捕逸 | BK・WP・PB |
| タッチアウト・挟殺 | TO・R/Oと処理順 |
| 併殺 | DPと処理順、対象2人それぞれのマスにアウト順 |

アウト順は回全体のI・II・III。走塁の記号は到達した塁の区画に配置し、長い処理順・同じ区画の追記が多い場合はマスの下にも全文を残す。得点は赤い○、残塁はℓ。守備方向が不明な安打・フライは「?」として推測しない。

## 入力時の確認

- 併殺は2人のアウトと成立順を指定する。
- 第3アウトでは種類と生還の先後を指定する。フォースアウト・打者の一塁到達前の第3アウトでは得点を認めない。
- 四死球は押し出される走者だけを進める。ボークは全走者を1つ進める。
- 安打後の走塁死は、安打を記録後、別の走塁イベントとして入力する。
- ワンヒットワンエラーは安打だけで到達した塁と最終到達塁を分ける。既存走者の進塁を自動で失策扱いにはしない。

## 検証と限界

101件の自動テストで旧イベント互換、集計、追加プレー、取消、アウト順、得点抑止を確認。追加17種類は実画面で選択・記録を確認し、375px幅で入力と用紙の横スクロールを確認した。

写真の各プレーを記録できるが、記入法の全流派・細かな手書き配置を完全再現するものではない。投球ごとのS/B、進塁させた打者の丸付き打順、交代情報、公式記録の自動裁定、端末間の同期、PDF出力は未実装。成績は暫定。記録・取消は同じブラウザ内に保存され、再読み込み後も復元する。

参照：ユーザー提供の用紙写真・記号早見表、および[ノート本舗のスコアブック](https://notehonpo.com/nn-yakyu/)。


## 保存の扱い

- 保存対象は現在のサンプル対戦カード1試合。記録済みイベントを形式バージョン・選手ID一覧とともに保存する。未確定の入力欄は保存対象外。
- 保存に成功してから試合状況を更新する。容量不足などで失敗した操作は反映せず、入力欄を残して再試行できるようにする。
- 読込完了までは記録・取消を無効にし、初期状態が保存データを消すことを防ぐ。
- 別タブの更新はWeb Locksと更新前データの比較で検知する。古いタブは入力を止め、再読み込みを案内する。
- 不正な形式や選手・打順・進塁の不整合がある保存データは上書きしない。
- 端末間・ブラウザ間・異なるURLの同期はない。ブラウザのサイトデータを消すと記録も消える。
- PC画面で安打→再読み込み、盗塁→再読み込み→取消→再読み込み、本塁打の得点復元、別タブの上書き防止を確認。保存容量不足・不正データは自動テストで検証。
